Concept: TypeScript

TypeScript is JavaScript with types. Types tell you what kind of data a variable holds.

JavaScript: let name = "Pavan" (could be anything later)

TypeScript: let name: string = "Pavan" (MUST be a string)

This catches bugs BEFORE you run your code!

Line 21-22 "@/*": ["./*"] - This is a path alias. Instead of writing:
import { connectDB } from "../../lib/db"
You can write:
import { connectDB } from "@/lib/db"
Much cleaner!

db.ts
lib/db.ts

Purpose: Connects your app to MongoDB database.

// Line 1: Import mongoose library
import mongoose from "mongoose";

// Line 3: Get database URL from environment variables
const MONGODB_URI = process.env.MONGODB_URI as string;

// Lines 5-7: Safety check - crash if no database URL
if (!MONGODB_URI) {
  throw new Error("Please define MONGODB_URI in .env.local");
}

// Lines 9-13: Caching trick for Next.js
let cached = (global as any).mongoose;
if (!cached) {
  cached = (global as any).mongoose = { conn: null, promise: null };
}

// Lines 15-26: The main function
export async function connectDB() {
  // If already connected, return existing connection
  if (cached.conn) {
    return cached.conn;
  }

  // If not connecting yet, start connecting
  if (!cached.promise) {
    cached.promise = mongoose.connect(MONGODB_URI).then((mongoose) => mongoose);
  }

  // Wait for connection and return it
  cached.conn = await cached.promise;
  return cached.conn;
}

Line-by-Line Breakdown:

Line 1 import mongoose from "mongoose";
This brings in the mongoose library. Mongoose is like a translator between JavaScript and MongoDB.
Line 3 const MONGODB_URI = process.env.MONGODB_URI as string;
process.env = Environment variables (secret settings stored outside code)
MONGODB_URI = Your database connection URL (like mongodb+srv://user:pass@cluster.mongodb.net/dbname)
as string = TypeScript: "I promise this is a string"
Lines 9-13 let cached = (global as any).mongoose;
Why cache? In Next.js, code can run multiple times. Without caching, you'd create a NEW database connection every time = bad!
global = A special object that persists across all code runs
We store the connection here so we only connect ONCE.
Line 15 export async function connectDB()
export = Other files can use this function
async = This function does something that takes time (database connection)
function connectDB() = The function name
Concept: Async/Await

Some operations take time (like connecting to a database). JavaScript doesn't wait - it moves on.

async marks a function as "contains waiting operations"

await means "wait here until this finishes"

// WITHOUT await:
const data = fetch("/api/data");  // data = Promise (not actual data!)

// WITH await:
const data = await fetch("/api/data");  // data = actual data!
Concept: Environment Variables

Secrets (like database passwords) should NEVER be in your code. Instead:

1. Create a .env.local file

2. Add: MONGODB_URI=mongodb+srv://user:password@cluster.mongodb.net/mydb

3. Access in code: process.env.MONGODB_URI

The .env.local file is in .gitignore, so it's never uploaded to GitHub!

Line-by-Line Breakdown:

Lines 3-7 export interface IUser extends Document { ... }
interface = TypeScript way of defining a shape/contract
extends Document = IUser also has all MongoDB document properties (like _id)
This tells TypeScript: "A User must have name, email, and password, all strings"
Lines 9-16 const UserSchema = new Schema({ ... })
Schema = The actual database structure (MongoDB needs this)
required: true = This field MUST be provided
unique: true = No two users can have same email
timestamps: true = Automatically track when created/updated
Lines 19-20 mongoose.models.User || mongoose.model("User", UserSchema)
This is a safety trick for Next.js:
• First, check if User model already exists
• If yes, use the existing one
• If no, create a new one
Prevents "model already defined" errors!
Concept: Interface vs Schema

Interface (TypeScript): Tells YOUR CODE what shape data should have. Compile-time check.

Schema (Mongoose): Tells the DATABASE what shape data should have. Runtime check.

You need BOTH - one for TypeScript, one for MongoDB!

Purpose: Defines what a "Job Application" looks like.

import mongoose, { Schema, Document, Model } from "mongoose";

// TypeScript interface
export interface IJob extends Document {
  userEmail: string;          // Who owns this job
  company: string;
  role: string;
  status: string;             // Applied, Interview, Offer, etc.
  appliedDate: Date;
  notes?: string;             // Optional (note the ?)
}

// MongoDB Schema
const JobSchema: Schema<IJob> = new Schema(
  {
    userEmail: { type: String, required: true },
    company: { type: String, required: true },
    role: { type: String, required: true },
    status: {
      type: String,
      enum: ["Applied", "Online Test", "Interview", "Offer", "Rejected"],
      default: "Applied",
    },
    appliedDate: { type: Date, required: true },
    notes: { type: String },  // Not required
  },
  { timestamps: true }
);

const Job: Model<IJob> =
  mongoose.models.Job || mongoose.model<IJob>("Job", JobSchema);

export default Job;
Line 10 notes?: string;
The ? means this field is OPTIONAL. Users don't have to provide notes.
Lines 19-22 enum: ["Applied", "Online Test", ...]
enum = "enumeration" - a list of ALLOWED values
If someone tries to set status to "Banana", MongoDB will reject it!
Line 21 default: "Applied"
If no status is provided, automatically set it to "Applied"

6. API Routes (The Backend Brain)

API
route.ts
app/api/auth/signup/route.ts

Purpose: Handles user registration.

import { NextResponse } from "next/server";
import { connectDB } from "@/lib/db";
import User from "@/models/User";
import { hash } from "bcryptjs";

// POST /api/auth/signup
export async function POST(req: Request) {
  try {
    // 1. Get data from request
    const { name, email, password } = await req.json();

    // 2. Validate - all fields required
    if (!name || !email || !password) {
      return NextResponse.json(
        { ok: false, message: "All fields are required" },
        { status: 400 }  // Bad Request
      );
    }

    // 3. Connect to database
    await connectDB();

    // 4. Check if email already exists
    const existing = await User.findOne({ email });
    if (existing) {
      return NextResponse.json(
        { ok: false, message: "Email already registered" },
        { status: 400 }
      );
    }

    // 5. Hash the password (NEVER store plain text!)
    const hashedPassword = await hash(password, 10);
    // "password123" → "$2a$10$N9qo8uLOickgx2ZMRZoMy..."

    // 6. Create user in database
    await User.create({
      name,
      email,
      password: hashedPassword,
    });

    // 7. Return success
    return NextResponse.json(
      { ok: true, message: "User created successfully" },
      { status: 201 }  // Created
    );
  } catch (error) {
    console.error("Signup error:", error);
    return NextResponse.json(
      { ok: false, message: "Server error" },
      { status: 500 }  // Internal Server Error
    );
  }
}
Concept: Password Hashing

NEVER store passwords as plain text! If your database gets hacked, all passwords are exposed.

Hashing: A one-way transformation that can't be reversed.

"password123" → hash() → "$2a$10$N9qo8uLOickgx2ZMRZoMy..."

Even if hackers get the hash, they can't get the original password!

The 10 in hash(password, 10) is the "salt rounds" - how many times to scramble. More = more secure but slower.

Concept: HTTP Status Codes
CodeMeaningWhen to use
200OKRequest successful
201CreatedSomething was created (new user, new job)
400Bad RequestUser sent invalid data
401UnauthorizedUser not logged in
404Not FoundRequested resource doesn't exist
500Server ErrorSomething broke on the server
Concept: Try-Catch Error Handling

Wrap risky code in try-catch to handle errors gracefully:

try {
  // Risky code that might fail
  await connectDB();
  await User.create({ ... });
} catch (error) {
  // If anything above fails, this runs
  console.error("Something went wrong:", error);
  return NextResponse.json({ message: "Server error" }, { status: 500 });
}

Without try-catch, an error would crash your entire server!

route.ts

Purpose: Handles all job operations (Create, Read, Update, Delete).

// GET - Fetch all jobs for a user
export async function GET(req: Request) {
  const { searchParams } = new URL(req.url);
  const email = searchParams.get("email");  // Get ?email=... from URL

  await connectDB();
  const jobs = await Job.find({ userEmail: email }).sort({ createdAt: -1 });
  // find() = get all matching documents
  // sort({ createdAt: -1 }) = newest first

  return NextResponse.json({ ok: true, jobs });
}

// POST - Create a new job
export async function POST(req: Request) {
  const { userEmail, company, role, status, appliedDate, notes } = await req.json();

  await connectDB();
  const job = await Job.create({
    userEmail,
    company,
    role,
    status: status || "Applied",  // Default to "Applied"
    appliedDate: new Date(appliedDate),
    notes: notes || "",
  });

  return NextResponse.json({ ok: true, job }, { status: 201 });
}

// PUT - Update a job
export async function PUT(req: Request) {
  const { id, company, role, status, appliedDate, notes } = await req.json();

  await connectDB();
  const updated = await Job.findByIdAndUpdate(
    id,                            // Find by this ID
    { company, role, status, ... },  // Update with these values
    { new: true }                  // Return the updated document
  );

  return NextResponse.json({ ok: true, job: updated });
}

// DELETE - Remove a job
export async function DELETE(req: Request) {
  const { id } = await req.json();

  await connectDB();
  await Job.deleteOne({ _id: id });

  return NextResponse.json({ ok: true, message: "Job deleted" });
}

Concept: Array filter()
