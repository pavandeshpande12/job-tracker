1. JavaScript Fundamentals

What is the difference between let, const, and var? Easy
  • var - Old way, function-scoped, can be redeclared, hoisted
  • let - Block-scoped, can be reassigned, not hoisted
  • const - Block-scoped, cannot be reassigned, must be initialized
var x = 1;   // Avoid using var
let y = 2;   // Use when value will change
const z = 3; // Use by default (most common)
Best Practice: Always use const by default. Only use let if you need to reassign. Never use var.
What is the difference between == and ===? Easy
  • == (Loose equality) - Compares values after type conversion
  • === (Strict equality) - Compares both value AND type
"5" == 5    // true (string converted to number)
"5" === 5   // false (different types)

null == undefined   // true
null === undefined  // false
Always use === to avoid unexpected bugs from type coercion.
What is an arrow function and how is it different from a regular function? Easy
Arrow functions are a shorter syntax for writing functions: 
// Regular function
function add(a, b) {
    return a + b;
}

// Arrow function
const add = (a, b) => a + b;

// Arrow with body
const greet = (name) => {
    console.log("Hello");
    return `Hi ${name}`;
};
Key Differences:
  • Arrow functions don't have their own this - they inherit from parent
  • Cannot be used as constructors (no new)
  • No arguments object
  • Shorter syntax, implicit return for single expressions
What is async/await and why do we use it? Medium
async/await is a way to handle asynchronous operations (things that take time) in a readable way. 
// Without async/await (Promise chains)
fetch('/api/data')
    .then(res => res.json())
    .then(data => console.log(data))
    .catch(err => console.error(err));

// With async/await (cleaner!)
async function getData() {
    try {
        const res = await fetch('/api/data');
        const data = await res.json();
        console.log(data);
    } catch (err) {
        console.error(err);
    }
}
  • async - Marks a function as asynchronous
  • await - Pauses execution until the Promise resolves
In your project: Used in API calls like await fetch("/api/jobs") and database operations like await User.create()
What is a Promise? Medium
A Promise is an object representing a future value - something that will either succeed or fail. 
const promise = new Promise((resolve, reject) => {
    // Do something async
    if (success) {
        resolve("It worked!");  // Success
    } else {
        reject("It failed!");   // Failure
    }
});

// Using the promise
promise
    .then(result => console.log(result))   // Handle success
    .catch(error => console.log(error));   // Handle failure
Promise States:
  • Pending - Initial state, not yet resolved
  • Fulfilled - Operation completed successfully
  • Rejected - Operation failed
Explain map(), filter(), and reduce() Medium
These are array methods that create new arrays without modifying the original: 
const numbers = [1, 2, 3, 4, 5];

// MAP - Transform each element
const doubled = numbers.map(n => n * 2);
// [2, 4, 6, 8, 10]

// FILTER - Keep elements that pass a test
const evens = numbers.filter(n => n % 2 === 0);
// [2, 4]

// REDUCE - Combine all elements into one value
const sum = numbers.reduce((total, n) => total + n, 0);
// 15
In your project:
  • map() - Rendering job list: jobs.map(job => <Row />)
  • filter() - Filtering jobs by search/status
What is destructuring? Easy
Destructuring is a way to extract values from objects or arrays into variables: 
// Object destructuring
const user = { name: "Pavan", email: "pavan@email.com", age: 15 };
const { name, email } = user;
console.log(name);  // "Pavan"

// Array destructuring
const colors = ["red", "green", "blue"];
const [first, second] = colors;
console.log(first);  // "red"

// In function parameters
function greet({ name, age }) {
    console.log(`${name} is ${age}`);
}
greet(user);  // "Pavan is 15"
In your project: Used everywhere!
const { name, email, password } = await req.json();

What is the spread operator (...)? Easy
The spread operator expands arrays or objects: 
// Copying arrays
const arr1 = [1, 2, 3];
const arr2 = [...arr1, 4, 5];  // [1, 2, 3, 4, 5]

// Copying objects
const obj1 = { a: 1, b: 2 };
const obj2 = { ...obj1, c: 3 };  // { a: 1, b: 2, c: 3 }

// Merging objects (later properties override)
const defaults = { theme: "dark", size: "medium" };
const userPrefs = { size: "large" };
const settings = { ...defaults, ...userPrefs };
// { theme: "dark", size: "large" }
What is event.preventDefault()? Easy
It stops the default browser behavior for an event. 
// Without preventDefault - form refreshes the page
<form onSubmit={handleSubmit}>

// With preventDefault - we handle it ourselves
const handleSubmit = (e) => {
    e.preventDefault();  // Stop page refresh
    // Now handle form submission with JavaScript
    await fetch('/api/submit', { ... });
};
Common uses:
  • Forms - Stop page refresh on submit
  • Links - Stop navigation to href
  • Drag/drop - Prevent default drop behavior
What is localStorage? Easy
localStorage is browser storage that persists even after closing the browser: 
// Store data
localStorage.setItem("user", JSON.stringify({ name: "Pavan" }));

// Retrieve data
const user = JSON.parse(localStorage.getItem("user"));

// Remove data
localStorage.removeItem("user");

// Clear all
localStorage.clear();
Key points:
  • Stores only strings (use JSON.stringify for objects)
  • ~5MB limit per domain
  • Persists until manually cleared
  • Only accessible on client-side (browser)
In your project: Used to store logged-in user info:
localStorage.setItem("jat_user", JSON.stringify(data.user));
What is try-catch? Easy
try-catch handles errors gracefully without crashing your app: 
try {
    // Code that might fail
    const data = await fetchData();
    processData(data);
} catch (error) {
    // Handle the error
    console.error("Something went wrong:", error);
    showErrorMessage("Failed to load data");
} finally {
    // Always runs (optional)
    setLoading(false);
}
In your project: All API routes use try-catch to handle database errors and return proper error responses instead of crashing.

2. TypeScript

What is TypeScript and why use it? Easy
TypeScript is JavaScript with static types. It catches errors at compile time instead of runtime. 
// JavaScript - No error until runtime
function add(a, b) {
    return a + b;
}
add("5", 3);  // "53" - oops, string concatenation!

// TypeScript - Error caught immediately
function add(a: number, b: number): number {
    return a + b;
}
add("5", 3);  // ERROR: Argument of type 'string' is not assignable
Benefits:
  • Catch bugs before running code
  • Better IDE autocomplete and IntelliSense
  • Self-documenting code
  • Easier refactoring
What is an interface in TypeScript? Easy
An interface defines the shape/structure of an object: 
// Define the interface
interface User {
    name: string;
    email: string;
    age?: number;  // Optional (?)
}

// Use it
const user: User = {
    name: "Pavan",
    email: "pavan@email.com"
    // age is optional, so we can skip it
};

// TypeScript will error if you miss required fields
const badUser: User = {
    name: "Test"
    // ERROR: Property 'email' is missing
};
In your project: Used in models like interface IUser and interface IJob
What is the difference between interface and type? Medium
Both define object shapes, but have subtle differences: 
// Interface - can be extended/merged
interface Animal {
    name: string;
}
interface Dog extends Animal {
    breed: string;
}

// Type - more flexible, can be unions
type Status = "pending" | "approved" | "rejected";
type NumberOrString = number | string;

// Type for objects
type User = {
    name: string;
    email: string;
};
When to use:
  • interface - For object shapes, especially when extending
  • type - For unions, primitives, or complex types
What does the ? mean in TypeScript? Easy
The ? marks something as optional: 
// Optional property
interface User {
    name: string;
    email: string;
    phone?: string;  // Optional - may or may not exist
}

// Optional chaining
const phone = user?.phone;  // Returns undefined if user is null/undefined

// Optional parameter
function greet(name: string, greeting?: string) {
    return `${greeting || "Hello"}, ${name}!`;
}

3. React.js

What is React? Easy
React is a JavaScript library for building user interfaces using components.

Key features:
  • Component-based - Build UIs from small, reusable pieces
  • Declarative - Describe what you want, React figures out how
  • Virtual DOM - Efficient updates by comparing virtual vs real DOM
  • One-way data flow - Data flows from parent to child
What is a component? Easy
A component is a reusable piece of UI. Think of it like a LEGO block. 
// Function component (modern way)
function Button({ text, onClick }) {
    return (
        <button onClick={onClick}>
            {text}
        </button>
    );
}

// Using the component
<Button text="Click me" onClick={handleClick} />
<Button text="Submit" onClick={handleSubmit} />
Benefits:
  • Reusable - Write once, use everywhere
  • Maintainable - Change one place, updates everywhere
  • Testable - Test components in isolation
What is JSX? Easy
JSX is a syntax extension that lets you write HTML-like code in JavaScript: 
// JSX
const element = <h1 className="title">Hello, {name}!</h1>;

// What it compiles to (you never write this)
const element = React.createElement(
    'h1',
    { className: 'title' },
    'Hello, ', name, '!'
);
JSX Rules:
  • Use className instead of class
  • Use htmlFor instead of for
  • All tags must be closed: <img />
  • Use {} to embed JavaScript expressions
  • Must return a single parent element
What is useState? Easy
useState is a React Hook that lets you add state (changeable data) to function components: 
import { useState } from 'react';

function Counter() {
    // Declare state variable
    const [count, setCount] = useState(0);
    //     ^        ^                 ^
    //   value   setter        initial value

    return (
        <div>
            <p>Count: {count}</p>
            <button onClick={() => setCount(count + 1)}>
                Increment
            </button>
        </div>
    );
}
Key points:
  • When state changes, component re-renders
  • Never modify state directly: count++ ❌
  • Always use the setter: setCount(count + 1) ✓
What is useEffect? Medium
useEffect lets you perform side effects (data fetching, subscriptions, DOM changes) in function components: 
import { useEffect, useState } from 'react';

function UserProfile({ userId }) {
    const [user, setUser] = useState(null);

    useEffect(() => {
        // This runs after render
        fetchUser(userId).then(data => setUser(data));
    }, [userId]);  // Re-run when userId changes
    //    ^
    // Dependency array

    return <div>{user?.name}</div>;
}
Dependency array explained:
  • [] - Run once on mount (like componentDidMount)
  • [value] - Run when value changes
  • No array - Run on every render (usually a bug!)
In your project: Used to fetch jobs when dashboard loads: 
useEffect(() => {
    fetchJobs();
}, []);
What are props? Easy
Props (properties) are how you pass data from parent to child components: 
// Parent component
function App() {
    return (
        <UserCard
            name="Pavan"
            email="pavan@email.com"
            onEdit={handleEdit}
        />
    );
}

// Child component receives props
function UserCard({ name, email, onEdit }) {
    return (
        <div>
            <h2>{name}</h2>
            <p>{email}</p>
            <button onClick={onEdit}>Edit</button>
        </div>
    );
}
Key points:
  • Props are read-only (immutable)
  • Data flows one way: parent → child
  • Can pass any type: strings, numbers, objects, functions
What is the difference between state and props? Medium
State Props
Managed inside the component Passed from parent component
Can be changed (mutable) Read-only (immutable)
Used for internal data Used to configure component
useState() Function parameters 
function Parent() {
    const [count, setCount] = useState(0);  // STATE
    return <Child count={count} />;         // Passed as PROP
}

function Child({ count }) {  // Receives as PROP
    // count is read-only here
}
What is conditional rendering? Easy
Showing different UI based on conditions: 
// Method 1: Ternary operator
{isLoggedIn ? <Dashboard /> : <Login />}

// Method 2: Logical AND (show if true)
{error && <ErrorMessage text={error} />}

// Method 3: Early return
function UserProfile({ user }) {
    if (!user) return <Loading />;
    return <Profile data={user} />;
}
In your project: 
{filteredJobs.length === 0 ? (
    <EmptyState />
) : (
    <JobTable jobs={filteredJobs} />
)}
Why do we need keys in lists? Medium
Keys help React identify which items have changed, added, or removed: 
// Good - unique ID as key
{jobs.map(job => (
    <JobCard key={job._id} job={job} />
))}

// Bad - index as key (can cause bugs)
{jobs.map((job, index) => (
    <JobCard key={index} job={job} />  // Avoid!
))}
Why indexes are bad:
  • If list order changes, indexes change
  • React might reuse wrong components
  • Can cause bugs with forms and animations
Rule: Use unique, stable IDs from your data (like _id from MongoDB).
What are controlled components? Medium
In controlled components, React controls the form input's value: 
function LoginForm() {
    const [email, setEmail] = useState("");

    return (
        <input
            type="email"
            value={email}                           // Controlled by state
            onChange={(e) => setEmail(e.target.value)}  // Update state
        />
    );
}
Benefits:
  • Single source of truth (state)
  • Can validate input in real-time
  • Can transform input (uppercase, format)
  • Easy to reset form

What is "use client" in Next.js? Medium
Next.js has two types of components:

What is an API? Easy
API (Application Programming Interface) is a way for different software to communicate.

Restaurant analogy:
  • You (frontend) = Customer
  • API = Waiter
  • Kitchen (backend/database) = Chef
You tell the waiter what you want, they get it from the kitchen and bring it back. You never go to the kitchen directly!

What is REST API? Medium
REST (Representational State Transfer) is a standard way to design APIs: 
// REST API design for "jobs" resource:

GET    /api/jobs        → Get all jobs
GET    /api/jobs/123    → Get job with ID 123
POST   /api/jobs        → Create new job
PUT    /api/jobs/123    → Update job 123
DELETE /api/jobs/123    → Delete job 123
REST principles:
  • Use HTTP methods (GET, POST, PUT, DELETE)
  • Stateless - Each request is independent
  • Use nouns for resources (/jobs, /users)
  • Return appropriate status codes
What are HTTP methods (GET, POST, PUT, DELETE)? Easy
Method Purpose Example

POST Create new data Add new job
PUT Update existing data Edit job details
DELETE Remove data Delete a job
What are HTTP status codes? Easy
Status codes tell you if a request succeeded or failed:

What is MongoDB? Easy
MongoDB is a NoSQL database that stores data as documents (like JSON): 
// MongoDB document (like JSON)

Why MongoDB?

What is the difference between SQL and NoSQL? Medium
SQL (MySQL, PostgreSQL) NoSQL (MongoDB)
Tables with rows and columns Collections with documents
Fixed schema (strict structure) Flexible schema
Relationships via foreign keys Embedded documents or references
Good for complex relationships Good for rapid development
What is Mongoose? Easy
Mongoose is an ODM (Object Document Mapper) - it lets you define schemas and interact with MongoDB using JavaScript: 
// Without Mongoose (raw MongoDB)
db.collection('users').insertOne({ name: "Pavan", email: "..." });

const User = mongoose.model('User', userSchema);
await User.create({ name: "Pavan", email: "..." });
Mongoose provides:
  • Schema definitions with validation
  • Type checking
  • Middleware/hooks
  • Query helpers
  • Virtual properties
What is a Schema in MongoDB/Mongoose? Easy
A schema defines the structure and rules for documents:

7. Authentication & Security

Why do we hash passwords? Easy
Never store passwords as plain text! If your database is hacked, all passwords are exposed. 
// BAD - Plain text (hackable!)
{ password: "secret123" }

// GOOD - Hashed (safe!)
{ password: "$2a$10$N9qo8uLOickgx2ZMRZoMy..." }
How hashing works:
  • One-way transformation (can't reverse)
  • Same input always = same hash
  • Tiny change = completely different hash
// Signup: Hash the password before storing
const hashedPassword = await hash("secret123", 10);
await User.create({ password: hashedPassword });

// Login: Compare entered password with stored hash
const isValid = await compare("secret123", user.password);
// Returns true if they match
What is bcrypt? Medium
bcrypt is a password hashing algorithm that's intentionally slow (to prevent brute-force attacks): 
import { hash, compare } from "bcryptjs";

// Hash a password (10 = salt rounds)
const hashedPassword = await hash("myPassword", 10);
// "$2a$10$N9qo8uLOickgx2ZMRZoMy..."

// Compare password with hash
const isMatch = await compare("myPassword", hashedPassword);
// true

const isMatch2 = await compare("wrongPassword", hashedPassword);
// false
Salt rounds (10):
  • Higher = more secure but slower
  • 10 is a good default balance
  • Each increase doubles the time
What are environment variables and why use them? Easy
Environment variables store sensitive config outside your code: 
// .env.local file (NEVER commit this!)
MONGODB_URI=mongodb+srv://user:password@cluster.mongodb.net/mydb
JWT_SECRET=super-secret-key-12345
API_KEY=abc123xyz

// Access in code
const dbUrl = process.env.MONGODB_URI;
const secret = process.env.JWT_SECRET;
Why use them?
  • Keep secrets out of code
  • Different values for dev/production
  • .env.local is in .gitignore (not uploaded to GitHub)
  • Easy to change without code changes
How does your login flow work? Medium
1. User enters email + password
   ↓
2. Frontend sends POST to /api/login
   ↓
3. Backend finds user by email in database
   ↓
4. Backend compares password with stored hash (bcrypt)
   ↓
5. If match: Return user info (name, email)
   If no match: Return error
   ↓
6. Frontend stores user in localStorage
   ↓
7. Frontend redirects to /dashboard
   ↓
8. Dashboard checks localStorage - if empty, redirect to /login

What is Flexbox? Easy
Flexbox is a CSS layout system for arranging items in rows or columns: 
.container {
    display: flex;              /* Enable flexbox */
    flex-direction: row;        /* row | column */
    justify-content: center;    /* horizontal alignment */
    align-items: center;        /* vertical alignment */
    gap: 16px;                  /* space between items */
}

/* Tailwind equivalent */
<div class="flex flex-row justify-center items-center gap-4">
What is CSS Grid? Medium
CSS Grid is for two-dimensional layouts (rows AND columns): 
.container {
    display: grid;
    grid-template-columns: repeat(3, 1fr);  /* 3 equal columns */
    gap: 20px;
}

/* Responsive grid */
grid-template-columns: repeat(auto-fit, minmax(300px, 1fr));
/* Creates as many 300px+ columns as fit */

/* Tailwind */
<div class="grid grid-cols-3 gap-5">
In your project: Stats cards use grid for responsive layout.
What is glassmorphism? Easy
Glassmorphism is a design trend that creates a "frosted glass" effect: 
.glass-card {

    backdrop-filter: blur(20px);           /* Blur what's behind */

    box-shadow: 0 4px 24px rgba(0, 0, 0, 0.3);

Key properties:
  • backdrop-filter: blur() - Blurs background
  • rgba() - Semi-transparent colors
  • Subtle borders and shadows

How does filtering work in JobList? Medium
// State for filters
const [search, setSearch] = useState("");
const [filterStatus, setFilterStatus] = useState("All");

// Filtering logic
const filteredJobs = jobs.filter((job) => {
    // Check if company OR role matches search
    const matchesSearch =
        job.company.toLowerCase().includes(search.toLowerCase()) ||
        job.role.toLowerCase().includes(search.toLowerCase());

    // Check if status matches filter (or "All" shows everything)
    const matchesStatus =
        filterStatus === "All" ? true : job.status === filterStatus;

    // Job must match BOTH conditions
    return matchesSearch && matchesStatus;
});
